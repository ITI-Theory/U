Design for it: everything Sherlock knows is data in the registry, addressable by document, claim, scale level and concept, so the app can show it.

Design decisions (made for the end state)

  • D1. Claims are data; Lean is the judge. Each affidavit’s claims live in registry/affidavits/<doc>.yaml: id, quote, lines, kind, reading, formal form, verdict, label, the Lean theorem that proves it, disposition. The Lean files prove; the registry describes. One format feeds the findings report, the release gate, cross-document values (4), structure mapping (5) and the Law chapter (6). A check ties each finding to an existing, compiled theorem.
  • D2. One relational vocabulary. Formal forms use OpenCyc constants and CycL-shaped sentences (predicate and arguments), including numeric claims (quotedValue doc quantity value unit). Programme concepts used by several documents (the Soma-Field, scale levels, the score) are defined once, in a shared TTheoryVocabularyMt inheriting UniversalVocabularyMt, not per paper. Structure mapping needs the same predicates across documents.
  • D3. A microtheory per document, and per reading. <Doc>Mt inherits TTheoryVocabularyMt; two readings of one claim get two microtheories. Cross-document consistency is a microtheory inheriting several document microtheories: a contradiction there is between documents.
  • D4. Freeze and version. An affidavit names its document’s commit and SHA-256. When a document is fixed, its new version gets a new affidavit; the old one stays (precedent, for the Law book).
  • D5. Python extracts and reports, Lean decides. Scripts read sources and write data (JSON, YAML, reports); Lean reads data at run time where it judges many items (the ledger) rather than having Lean generated, except the knowledge base itself.
  • D6. Cost-aware layout. Arithmetic affidavits are core Lean (seconds); OpenCyc typing imports UniversalVocabularyMt (1-5 minutes, a few GB), one module at a time; anything that changes the generated KB (rules) means an overnight rebuild, run by the author.
  • D7. AI extracts, a person or a second check confirms. The extraction prompt is in docs/SHERLOCK.md; one in eight candidates was wrong on ZSF, so every candidate is verified before it becomes Lean.
  • D8. Claims are anchored by their quote, not by line numbers (author, 11 Oct: “if I delete a line, is that an error or an improvement?”). A delta re-finds each claim’s quote in a new version and classifies it: unchanged (lines moved), edited (re-extract, re-check), gone (a contradicted finding gone is probably the fix; a supporting claim gone, or a value other documents quote, is a warning); text no claim covers is new and gets the extraction prompt, on the delta only. Sherlock proposes, the author confirms. Line numbers are derived.
  • D9. Numbers are data. Arithmetic claims use a small library of Lean templates (count equals list length, two values differ, sum, ratio within a range, monotone) that read their values from the registry, so an edited number is re-checked without editing Lean. Hand-written Lean stays for what the templates cannot say.
  • D10. Equations have formal twins. A labelled equation gets a formal twin (SymPy or Lean) and the document a symbol table (each symbol’s type and unit, declared once); Sherlock checks that the LaTeX and the twin agree, the units (an exponent must be dimensionless: delete the t from e^{-iEt/ħ} and it fails), unbound variables and values at the paper’s own parameters. Arbitrary LaTeX is not parsed. Visualize’s expect_* checks are the first, partial form of this.
  • D11. Language models at the ends, Lean in the middle (author, 11 Oct). A language model extracts claims and proposes mappings at the start (candidates, D7); Lean decides; NotebookLM is the final UAT check, a reader’s eye on the published version (do the fixes read right; does a reader still find the problem). The NotebookLM experiments measure how far a model gets alone; a locally run model with Sherlock choosing what it sees (chain finder, the slice) is the comparison: retrieval by Lean, explanation by the model.
  • D12. OpenCyc classes as Lean types (11 Oct, spike: sherlock/Types/Spike.lean, 62 s). A thin typed layer over the same facts: Inst m c is collection c as a Lean type (the terms microtheory m says are its instances, each with its proof); genls gives a coercion (Inst.up); disjointWith gives Inst.apart (one term with both types is Holds m .falsum, so no coercion between disjoint types can be added consistently). On P11: with Percept := Inst Z "Perceiving" and Pole := Inst Z "MathematicalObject", a function about poles applied to a percept is rejected by the compiler (“Application type mismatch: has type Percept but is expected to have type Pole”); the correspondence reading (occursAt q p) type-checks; and no_percept_is_a_pole is proved. A category error becomes a type error in the formal parts; prose is still the affidavits’ job. Open for the author: how the programme’s Lean gets the types. (a) The programme’s Lean imports Sherlock’s KB: exact, but every programme build then loads UniversalVocabularyMt (about a minute and several GB per process). (b) Recommended: a generated slice: make -C sherlock types writes a small standalone module (the concept registry’s classes as types, the genls coercions the chain finder found, the disjointness facts between them, as axioms), and Sherlock certifies in its own build that each axiom is a theorem of the full KB. Programme builds stay light, and the axioms are checked, not trusted. Then: the concept registry’s classes become types; the app’s type guard reads the generated table (which coercions exist). Decided (author, 11 Oct 22:00): (a), the full KB, slice first. The author’s working method for big ontology files: take a small slice (the first few hundred lines), fix its errors, widen it, and only then run the whole. So: the generated slice (b) is the development loop (seconds per run), and the release imports the full KB, where the slice’s axioms become theorems proved by the chain finder. Already the pattern elsewhere: MT=... in lean-gen, 8,000-fact parts, the spike importing one microtheory.
